Utiliser l API Mboka Services

L API connecte clients et prestataires locaux. Son prefixe est /api/mboka-services/v1.

Faire une premiere requete

Demarrer PostgreSQL puis Laravel depuis le dossier du projet :

powershell -NoProfile -ExecutionPolicy Bypass -File scripts/postgres.ps1 start
php artisan serve

Consulter le catalogue public :

GET http://127.0.0.1:8000/api/mboka-services/v1/categories
Accept: application/json
X-Locale: fr

Les langues disponibles sont fr, en et ln. Le fichier openapi.json est importable directement dans Postman : Import > fichier ou URL du fichier OpenAPI de la documentation.

Authentification mobile et web

L implementation actuelle utilise des tokens Bearer Sanctum, sur mobile comme sur le web. POST /auth/register et POST /auth/login retournent un token dans data.token. Pour les routes protegees :

Authorization: Bearer VOTRE_TOKEN
Accept: application/json

Le mot de passe d un compte est hache dans PostgreSQL. L empreinte du token est conservee dans personal_access_tokens. POST /auth/logout revoque le token courant. Redis ne remplace pas ce stockage.

GET /auth/me retourne le compte connecte. Les comptes client et provider peuvent s inscrire ; les droits administrateur ne sont pas accessibles par inscription publique.

Limites de connexion

POST /auth/login autorise 3 echecs par numero normalise + IP sur une fenetre de 15 minutes qui commence au premier echec. Les connexions reussies ne consomment pas ces essais. La quatrieme tentative est refusee jusqu a expiration de la fenetre, meme avec un mot de passe correct. Il existe aussi une limite de 30 requetes/minute par IP, tous numeros confondus.

En cas de blocage : HTTP 429 avec success=false, message, retry_after et en-tete Retry-After. Attendre ce delai avant de reessayer. Les memes compteurs sont utilises par le mobile et le web. PostgreSQL est le stockage par defaut ; Redis est activable par configuration.

Comprendre les modules

Module Usage
countries Pays et villes de reference
categories Groupes de metiers ; administration reservee aux admins
services Catalogue des metiers ; approbation admin des propositions prestataires
provider-services Offres des prestataires, prix et disponibilite
locations Adresse du profil, pays, ville et coordonnees
service-requests Demandes clients et suivi de l intervention
medias Images et videos de profil, portfolio et pieces jointes
notifications Notifications en base et suivi de lecture

Service, ProviderService et ServiceRequest representent respectivement un metier, une offre commerciale et une intervention demandee.

Parcours d une intervention

  1. Le client cree son compte et sa localisation.
  2. Il choisit un service approuve et cree une demande.
  3. Il peut choisir un prestataire immediatement ou l affecter plus tard.
  4. Le prestataire affecte accepte ou refuse.
  5. Une demande acceptee passe en cours puis terminee.

Statuts : pending -> accepted -> in_progress -> completed. Le refus donne rejected. Le client peut annuler une demande pending ou accepted, avec le statut cancelled. Les policies controlent l appartenance de la demande et les droits de chaque acteur.

Fichiers et erreurs

Pour les medias, utiliser multipart/form-data avec file, mediable_type, mediable_id et media_type. Une photo de profil doit etre une image. Les fichiers sont stockes sur le disque public ; la limite applicative actuelle est 500 Mo et depend aussi des limites PHP/serveur.

Les erreurs 401 indiquent une authentification manquante ou invalide ; 403 une action interdite ; 422 une validation ou regle metier non respectee ; 429 un depassement des limites. Si Redis est configure puis inaccessible, une erreur de connexion Predis est rendue en 503.

Ce qui reste a construire

La documentation publiee ne deploie pas le backend. Les sessions SPA par cookies, la reinitialisation du mot de passe, les paiements, Horizon et la recherche geographique par distance ne sont pas encore exposes comme fonctionnalites completes. PostGIS est installe et teste ; cela ne signifie pas qu une route de recherche par rayon existe deja.
