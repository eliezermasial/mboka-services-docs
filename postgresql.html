PostgreSQL et PostGIS sans Docker

Installation locale en place

Mboka dispose d'une copie native independante de PostgreSQL 18.6 et PostGIS 3.6.2 dans .local/postgresql18. Ces binaires ont ete copies depuis la distribution deja presente sur ce PC, avec sa licence. Aucune connexion ni modification n'a ete faite sur la base de l'autre logiciel.

  • Adresse : 127.0.0.1:5433 (le port 5432 est occupe par une autre application).
  • Base de developpement : mboka_services.
  • Base de tests : mboka_services_test.
  • Utilisateur Laravel : mboka_app, sans droits superutilisateur ni creation de bases ou de roles.
  • Les identifiants Laravel sont dans .env. Ceux de l'administrateur local sont proteges avec Windows DPAPI dans .local/postgres-admin.xml, pour le compte Windows qui a initialise l'instance.
  • Donnees : .local/pgdata. Journal : .local/postgresql.log.
  • Parametres locaux : shared_buffers=32MB, max_connections=30, fuseau Africa/Kinshasa.

Depuis le dossier du projet, dans PowerShell :

powershell -NoProfile -ExecutionPolicy Bypass -File scripts/postgres.ps1 start
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/postgres.ps1 status
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/postgres.ps1 stop

La base ne demarre pas automatiquement avec Windows : utiliser start avant Laravel et stop pour liberer la memoire. Ne pas deplacer ou supprimer .local pendant son fonctionnement. .local est ignore par Git et contient des donnees privees : ce n'est pas un dossier temporaire a nettoyer.

Les migrations et les seeders ont ete executes sur la nouvelle base locale. La base MySQL n'a pas ete effacee ni transferee. Une copie de l'ancien .env est conservee dans .local/mysql.env.backup.

php artisan migrate
php vendor/phpunit/phpunit/phpunit --do-not-cache-result

PHP doit charger pdo_pgsql, en CLI et dans le serveur HTTP. Les tests utilisent PostgreSQL et la base dediee mboka_services_test, dont les tables applicatives sont recreees par RefreshDatabase. Ne jamais donner le nom de la base de developpement ou de production a cette configuration de tests.

Installation sur un autre PC ou serveur

Installer PostgreSQL 18 et un bundle PostGIS 3.6 compatible via les distributions officielles. Sur Windows, Stack Builder permet d'ajouter PostGIS. Ne pas recopier des binaires Windows sur Linux.

Dans psql, avec un compte administrateur :

CREATE ROLE mboka_app LOGIN;
-- Definir le mot de passe sans l'inscrire dans l'historique SQL :
\password mboka_app
CREATE DATABASE mboka_services OWNER mboka_app;
\connect mboka_services
CREATE EXTENSION IF NOT EXISTS postgis;
SELECT PostGIS_Full_Version();

Pour une machine de tests, creer aussi mboka_services_test avec le meme proprietaire et y activer PostGIS en administrateur.

Configurer DB_CONNECTION=pgsql, DB_HOST, DB_PORT, DB_DATABASE, DB_USERNAME et DB_PASSWORD dans .env. DB_URL doit rester vide si les parametres individuels sont utilises. Puis :

php artisan config:clear
php artisan migrate

Sur une nouvelle base locale uniquement, php artisan db:seed initialise les donnees de reference et un administrateur de demonstration avec des identifiants publics. Ne pas executer ce seeder tel quel en production.

Changer la connexion ne transfere pas les donnees MySQL. Conserver l'ancienne base et organiser un transfert si necessaire. Ne pas utiliser migrate:fresh sur une base contenant des donnees a conserver.

Production

Activer PostGIS avant les migrations, avec un compte autorise. Conserver les memes versions majeures PostgreSQL/PostGIS que localement, avec les correctifs appropries. Utiliser une distribution officielle maintenue ou un service gere compatible PostGIS.

Ne pas donner de droits superutilisateur au compte Laravel. Configurer les secrets hors du depot, les sauvegardes et la connexion TLS selon l'hebergeur (DB_SSLMODE, certificats si requis). Executer php artisan migrate --force lors du deploiement. Les fichiers .local et les identifiants locaux ne sont pas des artefacts de deploiement.

Etape spatiale suivante

Les colonnes latitude et longitude existent deja. PostGIS est active et un test verifie une recherche de proximite en metres. L'ajout d'un point geography(Point,4326), d'un index GiST et d'une route de recherche par distance reste une evolution distincte.
