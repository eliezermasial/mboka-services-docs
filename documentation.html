Maintenir la documentation

L adresse de publication de la documentation publique est https://eliezermasial.github.io/mboka-services-docs/ . Le code du backend reste dans son depot prive. Le depot public mboka-services-docs ne recoit que les fichiers statiques generes.

Generer en local

composer install
php scripts/build-docs.php
php -S 127.0.0.1:8090 -t build/docs

Ouvrir http://127.0.0.1:8090 . La reference Scramble directe est aussi disponible dans l environnement local sur http://127.0.0.1:8000/docs/api .

Le script genere la specification OpenAPI depuis les routes, Form Requests et Resources ; complete les reponses communes et les limites ; verifie que toutes les operations API sont presentes ; puis construit les pages HTML des guides. Le resultat est dans build/docs, ignore par Git.

A chaque fonctionnalite

  1. Mettre a jour les routes, validations, types PHP et PHPDoc des Resources.
  2. Completer les descriptions metier et exemples utiles dans les guides Markdown.
  3. Executer les tests et php scripts/build-docs.php.
  4. Commit et push sur develop.

GitHub Actions relance les tests sur une base PostgreSQL/PostGIS ephemere, genere la documentation puis publie le site. Les pull requests sont verifiees sans publication. Un echec de tests ou de generation empeche la mise a jour du site ; la derniere version publiee reste disponible.

Configurer l adresse du backend

DOCS_API_URL definit l URL complete de base de l API dans la specification. Par defaut : http://127.0.0.1:8000/api/mboka-services/v1 . La variable GitHub Actions du meme nom permet de pointer plus tard vers une API de developpement publique en HTTPS, sans modifier le code.

La documentation en ligne ne rend pas localhost accessible aux autres personnes. Les navigateurs peuvent bloquer les appels depuis une page HTTPS vers un serveur HTTP local. Pour tester aujourd hui, importer openapi.json dans Postman ou utiliser la documentation locale /docs/api. Pour un backend distant, configurer les origines CORS autorisees et utiliser HTTPS.

Publication et acces

Le workflow utilise une cle SSH de deploiement autorisee uniquement sur le depot public de documentation. Sa partie privee est un secret GitHub Actions du backend, DOCS_DEPLOY_KEY. Elle n apparait ni dans le depot public ni dans les artefacts du site. Le secret est reserve aux publications depuis develop, jamais aux pull requests.

Les seuls fichiers publies sont ceux de build/docs : pages, CSS, OpenAPI et metadonnees de generation. Le .env, les identifiants, les fichiers .local, les donnees PostgreSQL et le code PHP ne sont pas publies. Les guides sont publics : ne pas y ajouter de secrets ni de donnees de clients.

Scramble signale actuellement JR001 sur 10 Resources enveloppant des tableaux de resultats plutot qu un modele Eloquent. Ces avertissements sont non bloquants ; les Resources de modeles sont annotees et les schemas critiques sont verifies par les tests. Le build controle aussi les references OpenAPI et les identifiants d operations.
